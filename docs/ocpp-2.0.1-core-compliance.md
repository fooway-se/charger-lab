# OCPP 2.0.1 Core compliance work

This emulator represents the **Charging Station** side of OCPP 2.0.1 and is used to exercise CSMS implementations. The target is the Core certification profile in OCPP 2.0.1 Edition 4, with optional profiles and optional feature IDs excluded from new work unless a feature is already needed by a mandatory Core test.

This checklist is an implementation plan, not a claim of OCA certification. A passing repository test suite does not substitute for running the current OCTT/PICS test plan.

## Compliance basis

- OCPP 2.0.1 Edition 4, including Errata 2026-09.
- Charging Station PICS 3.0.5, which selects Core and excludes optional profiles/features from this target.
- OCPP 2.0.1 Test Procedure & Test Plans v3.2.1 (2026-07-09).
- Core now includes basic boot, authorization, configuration, transactions, remote control, secure firmware updates, and Security Profile 2.
- The software-stack test setup requires simulated/emulated station actions for plugging/unplugging, authorization with at least two tokens, suspending charging, cold booting, meter values during a transaction, firmware update and reconnect. The OCTT-specific API is provided separately by OCA, so repository integration tests are useful preparation but are not an OCTT result.

## Implementation sequence

Each item is a separate TDD step and gets its own commit after its focused tests pass.

1. [x] Implement `SecurityCtrlr.BasicAuthPassword` set, validation, persistence, and authenticated reconnect (`TC_A_09`, `TC_A_10`).
2. [x] Preserve changed connector state across disconnects and implement `OCPPCommCtrlr.OfflineThreshold` (`TC_B_51`, `TC_B_52`). The emulator default is 300 seconds; offline plug/unplug simulation queues TransactionEvents for reconnect delivery. The exact ongoing-transaction meter/update requirements in `TC_E_40` remain in step 5.
3. [x] Complete mandatory Core Device Model components/variables and inventory/report behavior (`TC_B_06`–`TC_B_53`). Added the mandatory Core variable inventory, including ClockCtrlr and DeviceDataCtrlr, security/network runtime values, transaction/authentication settings, and full-inventory connector/EVSE properties. Read/write settings are persisted and covered independently for aligned and sampled data. Unit tests pass; one full-suite remote-stop integration timeout passed on isolated rerun. OCTT verification remains.
4. [x] Complete Core network profile rejection and migration including certificate-root changes (`TC_B_43`, `TC_B_45`, `TC_B_46`, `TC_B_50`, `TC_B_57`). Network priority rejects missing configuration slots and security downgrades; security upgrades require a configured trust root. After reset the station uses the selected profile, trusts OCPP-installed CSMS roots together with workspace trust roots, and reports the active slot. Integration tests cover same-CSMS fallback and WSS migration to a new CSMS root. OCTT verification remains.
5. [x] Close transaction outbox, offline, retry timing, and CallError cases (`TC_E_28`–`TC_E_51`). Added a CSMS reconnect scenario that requests transaction status before receiving the queued offline event, verifies FIFO replay and its `offline` flag, then rejects another event once with `InternalError` and confirms same-uniqueId retry and success on the same connection. Unit tests cover active/ended/unknown queue status, configured maximum attempts, backoff scheduling, and FIFO blocking. OCTT verification remains.
6. [x] Verify required remote start/stop and Heartbeat trigger behavior (`TC_F_04`, `TC_F_08`, `TC_F_09`, `TC_F_20`). Fixed the remote-start cable timeout to report `EVConnectTimeout`; the CSMS integration verifies the `Ended` event with `stoppedReason: Timeout`, rejects an unknown `RequestStopTransaction`, exercises accepted remote stop, and confirms TriggerMessage Heartbeat response-before-request ordering. OCTT verification remains.
7. [x] Verify connector status and availability behavior across required targets and reboot states (`TC_G_01`–`TC_G_21`). Station-wide Inoperative during an active transaction now updates idle EVSEs immediately while preserving Occupied for the active EVSE. Unit tests cover persistence for station, EVSE, connector, and scheduled changes; CSMS integration verifies status ordering and EVSE state after reset. Full OCTT/PICS verification remains.
8. [x] Complete mandatory meter measurands and Started/Updated/Ended/clock-aligned behavior (`TC_J_01`–`TC_J_10`). Added persistent `Sample.Clock` transaction-end readings for AlignedDataCtrlr settings and ensured the latest collected samples are included in Ended on every transaction stop path. Unit and CSMS integration suites cover no-transaction and active clock-aligned readings, sample persistence, Transaction.Begin, periodic Updated, aligned Ended, and Transaction.End. Full OCTT/PICS verification remains.
9. [x] Complete secure firmware update and certificate management edge cases (`TC_L_01`, `TC_L_02`, `TC_L_03`, `TC_L_05`, `TC_L_06`, `TC_L_07`, `TC_L_08`, `TC_L_12`, `TC_L_13`, `TC_L_18`, `TC_M_01`, `TC_M_02`, `TC_M_07`, `TC_M_12`, `TC_M_13`, `TC_M_17`, `TC_M_18`, `TC_M_19`, `TC_M_20`, `TC_M_22`). CSMS integration tests cover signed download/verification/reboot, future install scheduling, invalid/missing signer data, failed download/signature/install verification, active-session deferral with both `AllowNewSessionsPendingFirmwareUpdate` values, and CA certificate validation/query/delete results. Firmware packages are never executed; `FIRMWARE_INSTALL_VERIFICATION_FAILURE_SHA256` lets a test harness select an image that simulates an installation verification failure. OCTT/PICS verification remains.
10. [x] Implement diagnostics log retrieval, customer-information handling, and CustomData behavior (`TC_N_25`, `TC_N_26`, `TC_N_27`, `TC_N_28`, `TC_N_30`, `TC_N_31`, `TC_N_32`, `TC_N_35`, `TC_N_36`, `TC_P_01`, `TC_P_03`). Diagnostics and security logs upload over HTTP(S), retry failures, redact IdTokens in OCPP messages and encoded customer data, and cancel a prior request when a second GetLog arrives. CustomerInformation reports matching local IdToken data, clears it only after any requested report has been delivered, clears without sending a report when `report` is false, and reports empty data for misses. Optional customerIdentifier and customerCertificate selectors remain unsupported. The CustomData vendorId is validated while additional vendor fields are preserved. Unit and full CSMS integration suites pass; OCTT/PICS verification remains.
11. [x] Enforce the Core TLS minimum and reject security-profile downgrades (`TC_A_06`, `TC_A_22`). OCPP secure WebSocket connections negotiate TLS 1.2 or 1.3. When a lower-version handshake is rejected, the emulator reports `InvalidTLSVersion` after it reconnects securely. `SetNetworkProfile` rejects a security profile below the active profile. Unit and station-to-CSMS integration tests cover both behaviors; OCTT/PICS verification remains.
12. [x] Complete the mandatory software-stack test-bench controls from the OCA procedure. The UI/API supports plug/unplug on every configured connector, RFID authorization with two distinct IdTokens, EV-side and EVSE-side charging suspension and resume, and cold boot with a new `PowerUp` BootNotification. Integration tests also verify meter values during charging, firmware update/reconnect, and log upload.
13. [x] Apply `TxCtrlr.StopTxOnInvalidId` to non-Accepted IdToken results from `TransactionEvent` (`TC_E_16` behavior where its conditional authorization prerequisites apply). Energy is suspended and the token cleared atomically with an `Updated` event. With the current `TxStopPoint=EVConnected`, false reports `ChargingStateChanged` / `SuspendedEVSE`; true reports `Deauthorized` / `EVConnected`. Two CSMS integration cases and an outbox persistence test pass.
14. [ ] Repository verification passes (`composer test`: 220 unit tests and 84 integration tests, 2026-11-15). Still execute every applicable mandatory Core case with the OCA Compliance Testing Tool (OCTT), resolve any failures, and reconcile the final PICS declaration. OCTT and its separately distributed test-lab API are not present in this repository, so repository tests are not an OCTT result.
